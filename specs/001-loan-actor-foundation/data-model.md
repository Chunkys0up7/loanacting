# Data Model — Loan-Actor Foundation

Phase 1 output of `/speckit-plan`. Defines every persisted entity and the loan's state machine. Foundation is single-node; clustering is deferred.

---

## Entities

### `%LoanActor.State{}`

In-memory state held by the GenServer; persisted via diary replay (not directly stored).

| Field | Type | Notes |
|---|---|---|
| `loan_id` | `String.t` (UUIDv7) | Stable for life. Generated at spawn. |
| `status` | `atom` | One of the values from the state-machine enum below. |
| `goals` | `[%Goal{}]` | Outstanding objectives the planning loop will pursue. |
| `context` | `map` | Open-ended key/value bag — PII-free by `PIIGuard`. |
| `version` | `non_neg_integer` | Monotonic; incremented on every `transition/2`. |
| `last_heartbeat_at` | `DateTime.t \| nil` | Set by the periodic loop. |

`transition/2` is the only legal mutation entrypoint. Direct struct updates outside this function are forbidden (custom Credo check `LoanActor.Credo.NoDirectStateMutation`).

### Status enum (state-machine states)

```
:spawned
:awaiting_documents
:documents_under_review
:awaiting_operator_approval
:processing
:completed
:errored
```

Foundation does **not** model the full mortgage lifecycle. These statuses are sufficient to exercise the harness, idempotency, HITL, and replay invariants. Subsequent intents will refine.

### `%LoanActor.Goal{}`

| Field | Type | Notes |
|---|---|---|
| `goal_id` | `String.t` | UUIDv7. |
| `description` | `String.t` | Human-readable. |
| `status` | `:open \| :satisfied \| :abandoned` | |
| `due_at` | `DateTime.t \| nil` | If set, planning loop checks against `last_heartbeat_at`. |

### `%LoanActor.Event{}`

Inbound message into the actor's mailbox or HTTP endpoint.

| Field | Type | Notes |
|---|---|---|
| `event_id` | `String.t` (UUIDv7) | Idempotency key (with `source`). |
| `source` | `:operator \| :system \| :test` | Required. Foundation enum; extensions require an amendment. |
| `type` | `atom` | One of the event-type enum below. |
| `payload` | `map` | PII-stripped by `PIIGuard` before diary append. |
| `created_at` | `DateTime.t` | Event-author clock; informational. |
| `received_at` | `DateTime.t` | Receiver clock; authoritative for ordering. |

### Event-type enum

```
:document_uploaded
:document_review_requested
:operator_approval_required    # emits HITL
:operator_approval_granted     # response to HITL
:operator_approval_denied      # response to HITL
:heartbeat                     # internally generated by periodic loop
:goal_set
:goal_satisfied
:goal_abandoned
:complete
:abort
```

### `%LoanActor.Diary.Entry{}`

Append-only diary record.

| Field | Type | Notes |
|---|---|---|
| `entry_id` | `{loan_id, sequence}` | Composite key. `sequence` is `non_neg_integer`, gap-free, monotonic per loan. |
| `loan_id` | `String.t` | |
| `sequence` | `non_neg_integer` | Local per-loan ordering. |
| `timestamp` | `DateTime.t` | Receiver clock. |
| `type` | `atom` | Same enum as `Event.type` plus `:spawned`, `:state_transition`, `:duplicate_rejected`, `:approval_conflict`, and *(0004)* `:tool_invoked`, `:tool_completed`, `:tool_failed`, `:skill_activated`. (`Entry.new/1` accepts any atom; the enum is normative documentation — extending it is a data-model edit, not a code change.) |
| `actor` | `String.t` | Operator id, or `"system"`. |
| `payload_hash` | `binary` (32 bytes BLAKE2b-256) | Hash of canonical-JSON of payload AFTER `PIIGuard`. |
| `payload_ref` | `binary \| nil` | Optional pointer (URI) into the (future) PII vault. `nil` in foundation. |
| `prev_hash` | `binary` (32 bytes) | BLAKE2b-256 hash of the previous diary entry's `payload_hash`, or 32 zero-bytes for entry 0 (genesis). |

**Invariant.** For every loan, `diary[N].prev_hash == BLAKE2b-256(diary[N-1].payload_hash)` for `N > 0`, and `diary[0].prev_hash == <<0::256>>`. This matches `contracts/diary-store-behaviour.md`. `verify_chain/1` walks the chain end-to-end and fails on any mismatch.

### `%LoanActor.HITLRequest{}` and `%LoanActor.HITLResponse{}`

| HITLRequest field | Type |
|---|---|
| `request_id` | `String.t` (UUIDv7) |
| `loan_id` | `String.t` |
| `prompt` | `String.t` |
| `options` | `[String.t]` (e.g., `["approve", "reject"]`) |
| `created_at` | `DateTime.t` |

| HITLResponse field | Type |
|---|---|
| `request_id` | `String.t` |
| `decision` | one of `options` |
| `comment` | `String.t \| nil` |
| `operator_id` | `String.t` |
| `responded_at` | `DateTime.t` |

Two responses to the same `request_id` → second is rejected, diary entry `:approval_conflict` appended.

### `%LoanActor.Tool.Spec{}` *(0004)*

| Field | Type | Notes |
|---|---|---|
| `name` | `String.t` | Registry key and AG-UI `tool_call_name`. |
| `description` | `String.t` | Human/skill-readable purpose. |
| `parameters` | `map` | JSON-schema **subset** (`type`/`properties`/`required`/`enum` only — hard cap per `contracts/tool-behaviour.md`). |

Returned by each tool module's `spec/0`. `%LoanActor.Tool.Context{loan_id, state, loop, actor, invocation_id}` accompanies every `execute/2`. Tools return **effects**; the Server applies them via `transition/2` (tools never mutate state).

### `%LoanActor.Skill{}` *(0004; supersedes `%Procedure{}`)*

| Field | Type | Notes |
|---|---|---|
| `id` | `String.t` | Pack directory name (`NNNN-kebab-slug`). |
| `name` | `String.t` | Front-matter. |
| `version` | `String.t` | Semver, front-matter. |
| `description` | `String.t` | **The trigger** — matched against `{status, event type, open goal descriptions}` (foundation: normalized substring). |
| `tools_required` | `[String.t]` | Validated against the tool registry at load time; unresolvable pack → rejected. |
| `body` | `String.t` | SKILL.md markdown below the front-matter. |
| `files` | `[Path.t]` | Reference files under the pack dir. |
| `path` | `Path.t` | Pack directory. |

Foundation ships exactly one pack: `priv/skills/0001-demo-document-request/` (SKILL.md + one reference file) to prove load → trigger-match → tool-resolution. Format contract: `contracts/skill-format.md`.

## State machine

```
              spawn
                │
                ▼
            ┌────────┐
            │spawned │
            └────┬───┘
                 │  :goal_set (:require, :income_doc)
                 ▼
       ┌─────────────────────┐
       │ awaiting_documents  │◄─────────────┐
       └────────────┬────────┘              │
            :document_uploaded              │
                    ▼                       │
       ┌────────────────────────┐           │
       │ documents_under_review │           │
       └──┬─────────┬───────────┘           │
          │         │                       │
:operator_approval_required                 │
          │         │ :goal_satisfied       │
          ▼         ▼                       │
┌──────────────────────────┐  ┌──────────┐  │
│ awaiting_operator_approval│  │processing│  │
└──┬───────────────────────┘  └────┬─────┘  │
   │ :operator_approval_granted    │        │
   │                               │        │
   │ :operator_approval_denied ────┼────────┘
   │                               │
   ▼                               ▼
┌──────────┐                  ┌─────────┐
│processing│                  │completed│
└─────┬────┘                  └─────────┘
      │ :complete
      ▼
 ┌─────────┐
 │completed│
 └─────────┘

Any state → :errored on unrecoverable handler exception (supervisor restarts via diary replay).
```

`LoanActor.State.Model` mirrors this diagram; `LoanActor.State.transition/2` enforces it. Illegal transitions raise `LoanActor.IllegalTransitionError` and produce a diary entry of type `:illegal_transition_attempted`.

## Identity and ownership

- `loan_id` is **the** identity. No platform-internal numeric ID is exposed.
- Diary entries reference loan only by `loan_id`; this is the basis for the later MISMO-overlay intent.
- The HTTP API uses `loan_id` in path parameters: `/loans/:loan_id/...`.

---

## PII boundary

`PIIGuard` (in `lib/loan_actor/pii_guard.ex`) is the gate every event payload passes through before the diary write. Foundation implementation:

- Reject payloads whose JSON serialization matches any pattern in `priv/pii_patterns.yml` (regexes for SSN, account numbers, etc.).
- Replace flagged values with `"<redacted>"` and append a `:pii_redacted` field listing redacted paths.
- Test `apps/loan_actor/test/pii_guard_test.exs` exercises a synthetic PII corpus (foundation: 200 cases).

A future intent introduces the actual PII vault; `PIIGuard` will then write to the vault and store the returned `payload_ref` in the diary entry.
